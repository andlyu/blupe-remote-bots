# Companion changes for cached home-scene startup

These patches are part of the implementation in this runner checkout. They are
**packaged for integration**, not applied to the user's active companion
checkouts and not deployed. The feature is not usable end to end until both
companion patches and the runner changes are integrated and installed together.

- `robot-controller.patch` targets `blupe-playground-robot-controller`: coherent
  capture and persistence, normal-completion Home/capture/Park lifecycle,
  queue-head offers, measured startup/settling telemetry, and safe Ruckig pacing.
- `session-api.patch` targets `blupe-evals`: authenticated planning offers and
  readiness receipts, capability negotiation, per-profile measured timing
  history, and queue-head/exclusive-robot checks.
- The corresponding `*-baseline.json` records original repository HEAD, exact
  before/after SHA-256 for every changed file, patch SHA-256, and isolated
  snapshot commit. The baselines include pre-existing uncommitted companion
  work, so checking out only the listed original HEAD may not reproduce them.

The active companion repositories already contained unrelated edits (including
station fault work). Their files were only read. Changes and tests were prepared
in independent snapshots under `/private/tmp/blupe-home-scene-c2a4/`; these durable
patches preserve all requested changes even after those temporary copies vanish.
No generated bytecode, test dependencies, credentials, or unrelated edits are
included in the patches.

## Application

Use an isolated checkout containing the current companion work and preserve its
unrelated changes. From this directory, verify the exact target files first:

```sh
python3 verify_baseline.py robot-controller /path/to/controller-checkout
python3 verify_baseline.py session-api /path/to/blupe-evals-checkout

git -C /path/to/controller-checkout apply --check /absolute/path/robot-controller.patch
git -C /path/to/blupe-evals-checkout apply --check /absolute/path/session-api.patch
```

Then apply those same patch paths with `git apply`. If baseline verification
fails, reconcile the named files in an isolated checkout; do not overwrite the
live working files or use a forced reset. Inspect the resulting diffs and run
the companion tests and integrated test before committing and deploying through
the repositories' normal workflows.

Station validation: `python -m pytest tests`, with `src` and
`src/blupe_controller/runtime` on `PYTHONPATH` and the YAM dependencies installed.
API validation covers `test_home_scene.py`, `test_session_api_service.py`,
`test_session_api_asgi.py`, `test_session_api_contracts.py`, and
`test_session_api_trajectory.py` under `tests/`.

Run the shared runner's ordinary Python and Node tests, then set
`BLUPE_HOME_SCENE_STATION` and `BLUPE_HOME_SCENE_API` to those checkouts and run
`python -m pytest codex-runner/tests/test_home_scene_integration.py -q -s`.
The integrated test uses the real gateway and localhost HTTP/WebSocket service,
with explicitly injected in-memory motor drivers and fixture model replies.
It never connects to the live station.

See [the behavior and limits](../../codex-runner/docs/HOME-SCENE-STARTUP.md).

## Recorded validation

`validation-results.json` preserves final test counts and command runtimes.
`simulation-timings.json` preserves the actual monotonic measurements from the
Astra API and Codex subscription simulations. Their fixture model calls took
approximately 1–4 ms; these are **not measurements of real Astra latency**. The
simulated station took approximately 0.52 seconds for startup/calibration and
3.87 seconds for Home (3.5 seconds commanded plus measured settling overhead).
The tests confirm sample learning and safe minimum-duration behavior, not a
field latency improvement or a field cache-hit rate. Both transports confirmed
zero commands and no extra Home/capture when cancelled during startup.

Final checks: runner Python **875 passed, 25 skipped**; Node **222 passed**;
station **131 passed**; API **44 passed**; integrated transport scenarios
**2 passed**. The runner also passed 243 subtests, station 23, and API 13.
Patch reverse checks, exact active-checkout baseline hashes, and forward
`git apply --check` all passed without changing those active checkouts.

## Deployment preparation — October 12

Custom station launchers can use the optional `scripts/with_home_scene.py` wrapper
with `BLUPE_HOME_SCENE_ENTRYPOINT` and `BLUPE_HOME_SCENE_CONFIG`. It installs after
the existing entry point has configured its operator, retaining its motion owner.
Legacy Home overrides forward the scoped duration hint to the existing base
planner. The deployed YAM1 linear planner preserves its path and speed bounds;
RoboHouse retains its Ruckig planner. Neither wrapper authorizes a robot run.

Release preparation additionally passed 195 tests on the clean current controller
branch, 13 focused station tests (including custom launcher ordering), 49 hosted
candidate checks with 18 subtests, 44 API checks with 13 subtests, 35 checks in the
exact Linux API image, and both complete simulated transport scenarios.
